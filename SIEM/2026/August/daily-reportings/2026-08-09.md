# Day 3 — SSH Authentication Failure Investigation & SOC Documentation

**Date:** August 9, 2026
**Environment:** Kali Linux · Ubuntu Server · Wazuh SIEM
**Focus:** SSH authentication monitoring, incident investigation, runbooks, and incident documentation

---

## Objective

Simulate and investigate SSH authentication failures in the SOC homelab, validate the events at both the endpoint and SIEM levels, and establish a repeatable process for future investigations.

---

## Activities Completed

### 1. Kali–Ubuntu Network Configuration

* Configured static IPv4 addresses for the Kali Linux and Ubuntu Server VMs.
* Verified connectivity by initiating ICMP/ping requests from Kali to Ubuntu.
* Confirmed successful communication between the two lab systems.

### 2. SSH Authentication Failure Simulation

* Used Kali Linux to generate multiple failed SSH authentication attempts against the Ubuntu server.
* Used the activity to simulate suspicious login behavior within the isolated homelab.

### 3. Ubuntu Endpoint Log Verification

* Reviewed Ubuntu authentication/SSH logs after generating the failed attempts.
* Confirmed that the authentication failures were recorded at the endpoint.
* Identified relevant information including the source IP, target username, SSH session, and PAM authentication failures.

Example log:

```text
Aug 08 22:48:28 Ubuntu sshd-session[2788]: PAM 2 more authentication failures; logname= uid=0 euid=0 tty=ssh ruser= rhost=192.168.100.10 user=ubuntu
```

### 4. Wazuh Investigation

Investigated the resulting event in Wazuh and identified:

* **Rule:** 2502
* **Alert Level:** 10
* **Source IP:** `192.168.100.10`
* **Destination Host:** Ubuntu
* **Target Username:** `ubuntu`
* **MITRE ATT&CK:** T1110 — Brute Force

---

## 5. Runbook Development

Studied the purpose, structure, and practical use of SOC runbooks.

Created the first homelab investigation runbook:

**RB-2502-SSH-Authentication-Failures**

The runbook documents the investigation and response process for SSH authentication failure alerts associated with Wazuh Rule 2502.

---

## 6. Incident Documentation Template

Created a reusable Markdown incident-report template to standardize documentation for future investigations.

The template is designed to allow recurring alert information to be reused while leaving investigation-specific findings for the analyst to document.

---

## 7. Runbook Validation & Incident Reporting

After creating the runbook and template, performed the investigation again using the newly established process.

Documented the resulting incident as:

**RB-2502 — SSH Authentication Failures**

### Investigation Result

Multiple failed SSH authentication attempts against the Ubuntu account were detected.

The activity was consistent with possible brute-force/password-guessing behavior. The user confirmed that they did not initiate the attempts, so the activity was classified as suspicious and escalated to Tier 2 for further investigation.
