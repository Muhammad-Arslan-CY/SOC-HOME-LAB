# Work of the Day — pfSense to First SOC Incident Response

## Overview

Today I completed the setup and first practical SOC incident-response workflow using **pfSense + Wazuh**.

The main focus was moving from simply generating alerts to actually **investigating, classifying, documenting, and closing a security event**.

## 1. pfSense Setup

* Configured pfSense as the network firewall in the SOC lab.
* Verified that firewall/filterlog events were being generated.
* Confirmed that the traffic could be observed and forwarded toward Wazuh.

## 2. Wazuh Integration

* Connected pfSense firewall logs to Wazuh.
* Encountered several issues while configuring the Wazuh decoder and rules.
* Investigated why large amounts of generated traffic resulted in only a small number of visible alerts.
* Tested Wazuh log ingestion and rule processing.
* Fixed decoder/configuration issues and confirmed that pfSense events were reaching Wazuh correctly.

## 3. Custom Detection Rule

* Created my own Wazuh rule for detecting unusually frequent network activity.
* Configured it to trigger a **Level 10** alert when repeated events occurred within a short timeframe.
* Tested and adjusted the frequency/timeframe until the detection worked as expected.

## 4. Email Alerting

* Configured Wazuh email notifications for high-level alerts.
* Initially, emails were not being received.
* Investigated the SMTP connection and discovered that the Ubuntu mail server IP had changed.
* Updated the SMTP configuration.
* Confirmed that Wazuh successfully sent the Level 10 alert email.

## 5. Security Activity Simulation

* Generated high-volume network traffic in the lab to simulate possible DoS activity.
* pfSense recorded the traffic through its firewall logs.
* Wazuh detected the repeated activity and triggered the custom Level 10 rule.
* Received the alert through email.

## 6. Incident Response Activity

This was the main focus of today's work.

Instead of treating the alert itself as proof of an attack, I investigated the activity as a SOC analyst.

### Detection

* Received a Level 10 Wazuh alert for possible DoS activity.
* Identified the alert rule and timestamp.
* Confirmed that the alert was generated from pfSense firewall activity.

### Investigation

* Reviewed the source IP.
* Reviewed the destination IP.
* Checked source and destination ports.
* Identified the protocol as UDP.
* Checked the pfSense action and confirmed the traffic was being passed.
* Reviewed the event timestamps.
* Examined related events from the same activity.
* Determined the activity occurred over a short period.
* Checked the context of the source and activity.

### Classification

The activity was confirmed to be **authorized security testing** performed as part of the lab.

The alert was therefore not treated as a genuine malicious incident.

This demonstrated an important SOC principle:

> **An alert is not automatically an incident. It must be investigated and validated first.**

### Closure

* No containment was required.
* No escalation was required.
* The alert was documented and closed as authorized activity.
* The investigation and evidence were recorded for future reference.

## 7. SOC Documentation

Created a reusable **incident response runbook** for possible DoS activity.

Created an **incident documentation template** for recording:

* Alert information
* Evidence
* Investigation findings
* Timeline
* Classification
* Containment
* Escalation
* Closure
* Future improvements

This template will be reused for future incidents so that investigations follow a consistent process.

## Key Learning

Today's work moved beyond simply configuring a SIEM.

I practiced the complete basic SOC workflow:

**Alert → Collect Evidence → Investigate → Validate → Classify → Contain if Required → Document → Close**

The most important lesson was that **detecting suspicious activity and determining whether it is actually a security incident are two different tasks.**
