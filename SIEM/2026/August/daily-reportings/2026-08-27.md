## Executive Summary

Resolved critical log saturation and alert storm issues occurring during TCP flood attack simulations. By shifting noise filtering from the SIEM analysis tier down to the Network IDS engine level, the lab eliminated thousands of low-value stream decoder anomalies, prevented agent event queue overflows, and preserved high-fidelity detection rules for genuine denial-of-service attempts.

---

## Key Challenges & Technical Resolutions

### 1. Wazuh JSON Field Matching Remediation

* **Problem:** Custom silencing rules targeting parent rule `86601` failed to match noisy alerts, allowing thousands of duplicate events to bypass suppression.
* **Root Cause:** Custom rules used standard string matching (`<match>`) against structured JSON logs. Wazuh decodes Suricata `eve.json` natively, causing unstructured string matching to fail on nested keys.
* **Resolution:** Re-architected custom logic to target explicit schema keys using `<field name="data.alert.signature_id">`.

### 2. Suricata Rule File Syntax Recovery

* **Problem:** Suricata crashed and failed to initialize its local UNIX command socket (`/var/run/suricata/suricata-command.socket`), reporting a duplicate SID parsing error.
* **Root Cause:** A custom DoS signature (`1000002`) was appended to the active rule file (`/var/lib/suricata/rules/suricata.rules`) without a trailing newline, merging it directly into an existing Emerging Threats Tor rule (`2522759`).
* **Resolution:** Separated the merged rules into discrete lines, successfully restoring full compilation across all **52,554** active rules with **0** syntax failures.

### 3. Suricata Command Socket & Management Activation

* **Problem:** CLI socket control (`suricatasc`) returned `Connection refused (os error 111)` due to socket inactivity during systemd management.
* **Resolution:** Updated `unix-command.enabled` from `auto` to `yes` inside `/etc/suricata/suricata.yaml` and established live, non-blocking ruleset reloads via `suricatasc -c "reload-rules"`.

### 4. NIDS Engine-Level Rate Limiting & Suppression

* **Problem:** High-volume packet floods (`hping3 --flood`) generated thousands of secondary TCP state machine events (`2210004`, `2210008`, `2210022`, `2210023`, `2210027`), flooding `eve.json` and triggering Wazuh agent buffer warnings (`Agent event queue is full`).
* **Root Cause:** Decoder anomalies fired repeatedly on out-of-order and retransmitted SYN/SYN-ACK segments during stateless flooding.
* **Resolution:** Enabled global threshold management (`threshold-file: /etc/suricata/threshold.config`) in `suricata.yaml` and implemented rate-limiting/suppression controls:
* Directional rate limits (`track by_src` / `track by_dst`) throttled high-frequency events to **1 alert per 15 seconds**.
* Dropped excessive stream noise directly in memory before writing to disk, protecting both system I/O and SIEM storage.



### 5. SIEM Rulebase Sanitization

* **Problem:** Redundant silence rules existed in `local_rules.xml` that were no longer necessary.
* **Resolution:** Pruned rules `100017` and `100018` via the Wazuh Dashboard interface, maintaining a clean, performant detection ruleset.
