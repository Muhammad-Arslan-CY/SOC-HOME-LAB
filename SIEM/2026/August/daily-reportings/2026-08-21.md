## 1. Operational Overview

Host-based firewalls form the innermost perimeter of defense in depth.
---

## 2. Core Concepts for Security Analysts

### A. The Default Deny Baseline (Attack Surface Minimization)

* **Concept:** All ingress network traffic is discarded unless explicitly permitted by an operational rule. Egress traffic is monitored or permitted based on organizational policy.
* **SOC Impact:** Any packet hitting a default deny policy generates a dropped-packet log entry. A sudden cluster of dropped packets indicates either scanning activity or an internal host attempting unauthorized lateral connections.

### B. Ingress vs. Interface-Scoped Policies

* **Concept:** Firewalls evaluate packets based on the ingress interface, protocol, source subnet, and destination port.

### C. Telemetry Fidelity and Logging Tiers

* **Concept:** UFW provides variable logging rates (`off`, `low`, `medium`, `high`, `full`).
* **SOC Impact:**
* `low`: Logs all blocked packets that violate policy, as well as packets matching explicit log rules. Optimal for balancing disk I/O and SIEM ingestion cost while capturing scans.
* `medium`: Adds logging for allowed connections and invalid packets. Useful for short-term incident response or auditing new connection baselines.

## 3. Log Anatomy & Evidence Extraction

A standard UFW syslog entry recorded in `/var/log/ufw.log` or `/var/log/syslog` contains structured fields that must be extracted during triage:

```text
Aug 21 02:13:40 ubuntu kernel: [UFW BLOCK] IN=enp0s8 OUT= MAC=08:00:27:53:7e:17:08:00:27:5a:87:bc:08:00 SRC=192.168.10.20 DST=192.168.10.10 LEN=44 TOS=0x00 PREC=0x00 TTL=46 ID=59501 PROTO=TCP SPT=50675 DPT=8080 WINDOW=1024 RES=0x00 SYN URGP=0

```

### Key Field Reference

| Log Field | Extracted Value | Analyst Interpretation |
| --- | --- | --- |
| **Action** | `[UFW BLOCK]` | Packet was dropped by policy or rule. |
| **IN** | `enp0s8` | Ingress interface the packet arrived on. |
| **SRC** | `192.168.10.20` | Attacking/Scanning source IP address (IOC). |
| **DST** | `192.168.10.10` | Targeted local endpoint IP address. |
| **PROTO** | `TCP` | Transport protocol used. |
| **SPT** | `50675` | Ephemeral client port on the originating host. |
| **DPT** | `8080` | Targeted service/application port (e.g., alternate HTTP). |
| **Flags** | `SYN` | Indicates a connection establishment attempt (classic SYN scan). |
| **TTL** | `46` | Time To Live; provides clues regarding network distance and OS fingerprinting. |

## 4. Operational Playbook: Triaging Firewall Alerts in SIEM

1. **Initial Alert Verification:**
* Validate if the destination port corresponds to a known legitimate service on the asset.
* Determine if the action was `BLOCK` or `ALLOW`.


2. **Source IP Scope & Reputation:**
* Is the source internal (RFC 1918) or external?
* If internal: Check whether the source is a vulnerability scanner, domain controller, or an unauthorized endpoint.
* If external: Check threat intelligence feeds for known malicious scanners.


3. **Pattern Analysis:**
* **Single Port, Repeated Packets:** Likely a brute-force attempt or connection flood.
* **Multiple Sequential Ports, Single Source:** Port discovery / reconnaissance (MITRE ATT&CK T1046).
* **Sweep (Same Port Across Multiple Hosts):** Internal lateral movement scan.


4. **Escalation / Containment Criteria:**
* Escalate if a blocked external connection attempt is followed by successful egress traffic from the same host to that source IP.
* Escalate immediately if an internal host is identified scanning high-value management ports (22, 3389, 445) across the subnet.

---

## 5. Daily Assessment & Key Takeaways

* Raw firewall drops are high-volume, low-severity events until correlated with time windows, targeted port profiles, and authentication logs.
* Elevating SIEM alert rules from Level 2/Informational to Level 5+ should be reserved for actionable patterns (e.g., threshold-based scan detection) to avoid alert fatigue.
* Proper normalization (decoding `SRC`, `DST`, `DPT`, `PROTO`) is mandatory for accurate dashboard aggregation and correlation searches.
